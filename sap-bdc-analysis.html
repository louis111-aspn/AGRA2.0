Section 03 — Roadmap Detail

BDC 로드맵 항목별 분석

신뢰도 기준
아래 항목들은 SAP 공식 로드맵 및 커뮤니티 발표 기반으로 정리됩니다. 각 항목별로 원문 묘사와의 차이를 명시합니다.
Q2 2026 — Datasphere
① Transformation Flow: Star Schema Flattening
Datasphere
Data Engineering ML 최적화 Databricks 연동
핵심 스코프: SAP BW 등 기존 시스템의 스타 스키마(사실 테이블 + 차원 테이블) 구조를 ML/AI 플랫폼이 처리하기 최적화된 평탄화 테이블로 자동 변환. Databricks 연동 효율화가 주요 목적.

신뢰도 보정: 기능 방향성은 정확. 단, 원문의 "Claude의 환각 방지를 위한 최적화 피드"라는 묘사는 공식 발표에 없는 추론. 실제 목적은 ML 플랫폼 연동 효율화이며, Claude에 대한 직접 연관성은 공식 확인 불가.

실질적 의미: SAP 데이터를 Databricks 등 외부 ML 플랫폼에서 활용할 때 ETL 공수를 획기적으로 줄임. AI 추론의 입력 데이터 품질 향상 효과는 간접적으로 유효.
→ 효과: 중복 ETL 파이프라인 제거, 외부 ML 플랫폼과의 데이터 연동 효율 향상
② BDC Connect for BigQuery & Snowflake GA
BDC Connect
하이퍼스케일러 데이터 연동
핵심 스코프: Databricks(2025.10 GA)에 이어 BigQuery, Snowflake 연동 H1 2026 GA 예정. SAP 데이터를 각 플랫폼에서 직접 분석·ML 모델 학습에 활용 가능.

의미: SAP 데이터 사일로를 해소하고 기업의 기존 데이터 플랫폼 투자와 SAP AI를 연결하는 브리지 역할. 고객이 SAP 외부 AI 도구를 SAP 데이터 위에서 자유롭게 사용할 수 있게 됨.
→ 효과: SAP 데이터 기반 외부 ML 모델 학습 가능, 데이터 이동 최소화
Q2~Q3 2026 — Datasphere
③ AI-Assisted SQL Generation in View Builder
Datasphere · Joule API
Joule API 개발자 생산성 Human-in-the-Loop
핵심 스코프: Joule API를 활용한 자연어 → SQL 뷰 자동 생성. 개발자가 자연어로 요구사항 입력 시 복잡한 분석용 SQL 초안을 AI가 생성. Human-in-the-Loop 검토 프로세스 포함.

신뢰도 보정: 기능 방향성은 SAC AI 로드맵과 일치. 단, "Claude Code의 역량이 이식되는 첫 단계"라는 원문 표현은 과장. Joule 내부에서 어떤 모델이 작동하는지는 미공개 — Claude 직접 연동 확인 불가.

실질적 의미: SAP ABAP/CDS에 익숙하지 않은 현업 분석가도 복잡한 Datasphere SQL View를 생성할 수 있게 됨. 데이터 엔지니어링 진입 장벽 대폭 하락.
→ 효과: SQL 개발 공수 감소, 현업 분석가의 자력 데이터 추출 가능
Q3 2026 — SAC · BDC
④ AI-Assisted Prompt Insights Widget (SAC)
SAC · LLM 연동
대시보드 AI Governed Access Context 전달
핵심 스코프: 대시보드 설계자가 특정 차트·테이블 데이터와 사용자 프롬프트를 결합하여 LLM으로 직접 컨텍스트를 전송하는 위젯 배치 가능. 거버넌스 통제 하의 안전한 데이터 접근 보장.

신뢰도 보정: 기능 자체는 SAC AI 로드맵 방향과 일치. 단, "이것이 MCP가 SAC 화면단에 구현되는 모습"이라는 원문 묘사는 추론. 실제 아키텍처가 MCP 기반인지 내부 Joule API 기반인지는 공식 문서에서 구분되지 않음.

실질적 의미: 대시보드 자체가 AI와의 인터랙티브 인터페이스가 됨. 별도 AI 도구 전환 없이 데이터를 보는 맥락에서 바로 AI 분석 질의 가능.
→ 효과: 데이터 분석과 AI 질의의 워크플로우 통합, 거버넌스 준수 하의 LLM 활용
⑤ AI-Powered Story Insight Generation (SAC)
SAC · 자율 보고
자율 분석 Story 자동 생성 경영진 보고
핵심 스코프: 사용자의 질문과 비즈니스 맥락을 AI가 파악하여 시각화 차트, 트렌드 분석, 예측 인사이트가 포함된 SAC 스토리(대시보드 보고서)를 자율 생성.

신뢰도 보정: AI 기반 스토리 자동 생성 방향은 SAC AI 로드맵과 일치. 단, "CFO 지시 한 마디로 이사회 대시보드 전체를 End-to-End 자율 생성"하는 수준은 현재 스코프를 초과한 묘사. Q3 2026 시점은 "initial set" 수준의 초기 기능 출시로 봐야 함.

실질적 의미: 반복적·정형화된 경영진 보고서 초안 작성 자동화가 현실적인 첫 번째 효과. 완전 자율화는 중장기 목표.
→ 효과: 정형 보고서 작성 공수 감소, 분석가의 고부가가치 해석 업무에 집중 가능
⑥ BDC Connect for Microsoft Fabric GA
BDC Connect · Q3 목표
Microsoft Fabric 하이퍼스케일러
핵심 스코프: SAP BDC와 Microsoft Fabric 간 데이터 연동. SAP + Microsoft 양사가 공동 발표한 공식 로드맵으로 가장 신뢰도 높은 항목.

배경: SAP와 Microsoft는 Joule-Copilot A2A 상호운용성도 Q4 2026 GA 목표. BDC-Fabric 연동과 Joule-Copilot A2A가 결합되면 Microsoft 365 환경과 SAP 데이터가 실질적으로 통합되는 구조 완성.
→ 효과: Microsoft 생태계 고객의 SAP 데이터 접근성 극대화, 중복 ETL 제거

Section 05 — Strategic Implications

BDC 로드맵의 시장·전략적 시사점

시장 파급력
데이터 엔지니어링 역할의 재정의
  • SQL View 자동 생성으로 데이터 엔지니어의 단순 쿼리 작성 업무가 AI로 대체 — 아키텍처 설계와 비즈니스 로직 정의로 역할 이동
  • 현업 분석가의 데이터 자력 추출 가능 → BI 팀에 대한 의존도 감소
  • 하이퍼스케일러 연동으로 SAP 데이터를 Databricks·BigQuery에서 직접 ML 학습에 활용 — SAP 외부 AI 도구와의 경계 소멸
  • 중복 ETL 파이프라인 제거로 데이터 인프라 운영 비용 구조 변화
도입 현실성
실제 도입을 제한하는 구조적 조건
  • BDC 기능 대부분은 S/4HANA Cloud + Datasphere 라이선스 필요 — 온프레미스 고객은 접근 불가
  • Q3 2026 SAC AI 기능은 "initial set" — 완전 자율화까지는 추가 릴리즈 필요
  • 하이퍼스케일러 연동 효과 극대화는 기업의 Databricks/BigQuery/Fabric 기존 투자 전제
  • AI Story 자동화의 품질은 Datasphere의 데이터 거버넌스 성숙도에 직접 비례

Section 06 — Workforce Impact

BW/BI 컨설턴트 및 조직에 대한 영향과 대비책

국내에서 BDC 도입 고객은 단기적으로 제한적이며, SAP AI 전략의 실현 속도에도 불확실성이 존재함 — 위험도는 글로벌 전망보다 현저히 낮게 보정되어야 하며, 변화의 방향에 대비하는 점진적 역량 전환이 현실적 대응임
국내 BDC 도입 제약 — 현실 진단
글로벌 전망과 국내 현실의 괴리
  • BDC는 S/4HANA Public Cloud 위에 올라가는 레이어 — 국내 Public Cloud 전환 자체가 아직 초기 단계로, BDC 도입 고객 풀이 구조적으로 제한됨
  • Datasphere는 별도 라이선스 구매 필요 — 중견기업 이하는 비용 장벽으로 채택 가능성 낮음
  • 국내 데이터 주권·보안 규제 및 IT 조직의 보수적 성향으로 퍼블릭 클라우드 기반 AI 기능 채택 속도 둔화
  • 국내 BI 시장은 여전히 BW + Analysis for Office 중심 — SAC 전환 자체도 더딘 상황에서 SAC AI 자동화 충격은 단기 과장
SAP AI 전략 실패 시나리오
낙관론을 제한하는 구조적 리스크
  • Compute Cost 문제: 대규모 엔터프라이즈 트랜잭션에 실시간 LLM 추론을 적용하면 인프라 비용이 급증 — 실제 배포 범위를 제한하는 핵심 변수
  • Joule 품질 한계: 복잡한 비즈니스 로직 처리에서 AI 추론 오류 발생 시 신뢰도 타격 — 고객이 Human-in-the-Loop를 과도하게 유지하면 자동화 효과 반감
  • 멀티 LLM 경쟁: Microsoft(Copilot)·Google(Gemini) 연동이 강화되면 Claude의 '기본 추론 엔진' 포지션이 희석될 가능성
  • ECC 지속 사용: 국내 대기업 다수가 ECC 온프레미스 유지 — BDC AI 기능 접근 자체가 불가한 구조적 단절
업무 유형별 실질 위험도 — 국내 현실 기준으로 보정
업무 유형 글로벌 전망 국내 실질 위험도 국내 현실 / 보정 근거
ETL 파이프라인 구축 (DTP, 변환 루틴) 매우 높음 중간 Datasphere 도입 고객에 한정. ECC·BW 온프레미스 환경에서는 수년간 현행 유지
표준 보고서·쿼리 개발 (BEx, AfO) 매우 높음 중간 SAC 전환이 선행되어야 함. 국내 AfO 의존도 높아 SAC AI 자동화 충격은 단기 과장
InfoObject / InfoCube 설계 높음 낮음~중간 BW 신규 구축 프로젝트 자체가 감소 추세 — AI 대체보다 시장 수요 감소가 선행 요인
데이터 정합성 검증·오류 수정 높음 낮음 GR AI 에이전트는 Public Cloud + GR 사용 고객에 한정. 국내 적용 범위 제한적
데이터 거버넌스 정책 설계 낮음 낮음 BDC 도입 여부와 무관하게 데이터 거버넌스 중요성은 증가 — 안정적 역할 영역
비즈니스 도메인 요건 해석·번역 낮음 낮음 AI 도입 속도와 무관하게 핵심 가치 유지. 오히려 AI 도입 컨설팅 수요로 확대 가능
AI 에이전트 Tool·워크플로우 설계 신규 수요 중기 수요 국내는 2~3년 후 실수요 발생 예상. 선제 역량 확보 시 선점 효과 가능
BW/BI 컨설턴트 역할 전환 경로 — 4가지 트랙 (국내 현실 기준)
Track A — 데이터 아키텍트
▶ 즉시 유효 · 국내 수요 안정적
BW 스타 스키마·DataStore 설계 경험 → Datasphere Analytical Model 설계로 전환. BDC 도입 프로젝트에서 아키텍처 설계 역할은 AI 대체 불가. S/4HANA 마이그레이션 수요와 연동.
습득 역량: Datasphere Semantic Layer · Data Product 설계 · BDC 거버넌스
Track B — 비즈니스 도메인 전문가
▶ 즉시 유효 · AI 도입 속도와 무관
재무·공급망 등 특정 도메인 깊이 특화 → AI 에이전트의 비즈니스 요건 정의·검증 담당. BDC 도입 여부와 상관없이 핵심 가치 유지. SAP AI 전략이 지연되어도 도메인 전문성은 감가상각 없음.
습득 역량: IFRS·K-GAAP · 규제 컴플라이언스 · Human-in-the-Loop 거버넌스 설계
Track C — AI 에이전트 오케스트레이터
▶ 중기 (국내 2~3년 후 본격 수요)
MCP Tool 정의·Joule Studio 워크플로우 설계·n8n 자동화 구성 담당. 국내 BDC 도입 고객이 늘기 시작하는 시점에 선점 효과 발생. 지금 준비하면 2~3년 후 희소 역량이 됨.
습득 역량: MCP 표준 · Joule Studio · 프롬프트 엔지니어링 · n8n 워크플로우
Track D — AI 거버넌스·감리 전문가
▶ 중기 · 규제 강화 연동 수요
AI 에이전트 산출물의 정확성·Audit Trail 검증, 감사 수검 대응, 내부통제 체계 설계. 금융·상장사 중심으로 AI 거버넌스 규제가 강화될수록 수요 증가. BW/BI의 데이터 품질 판단 경험이 직접 활용됨.
습득 역량: XAI · 내부통제 설계 · K-SOX · AI 감사 프레임워크
