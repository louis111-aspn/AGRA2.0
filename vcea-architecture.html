핵심 기술SAP GR · RAP/BTP · ACDOCU · PartnerSegment
설계 정의 (Design Definition)
본 설계는 중간 연결그룹을 하나의 가상 연결실체(Virtual Consolidated Entity)로 변환한 후, 해당 실체를 상위 연결의 연결단위로 사용하는 순차연결 모델이다.
순차연결을 데이터 복사 문제로 보지 않고 연결실체 변환(Consolidated Entity Transformation) 문제로 재정의함으로써, SAP GR 표준 기능 범위 내에서 완전한 구현이 가능하다.
설계 철학 트랙 1 — GR 내 순차연결 트랙 2 — 외부 FS 업로드 RAP 개발 상세 운영 리스크 비교 및 선택
설계 철학 — Consolidated Entity Transformation
기존 SAP 순차연결 접근과의 근본적 차이, 연결실체 가상화 개념, 연결조정 비승계 원칙
기존 접근과의 차이
구분기존 접근 (GRDC Data Mapping)본 설계 (VCEA)
문제 정의 다단계 구조를 GR에 억지로 집어넣는 방법 중간 연결 완료 후 단일 연결실체로 변환
상위 연결의 인식 S1·S2가 개별 CU로 존재하거나 치환 처리 CG_P에서는 S1·S2의 연결 결과가 M 연결실체에 흡수되어 표현됨
내부거래 처리 파트너 치환 · GRDC 매핑 필요 PartnerSegment + Reclass Rule + ICMR 표준 처리
연결조정 승계 하위 조정 분개가 상위로 누적 연결조정 분개 비승계. 연결 결과만 입력 데이터로 사용
추가 라이선스 GRDC 별도 라이선스 필요 표준 GR + RAP 개발만으로 구현
연결조정 비승계 원칙 — 핵심 차별점
핵심 원칙 (Core Principle)
본 설계는 연결조정 분개를 상위 연결으로 승계하지 않는다.
연결조정 결과가 반영된 연결재무제표만 상위 연결의 입력 데이터로 사용한다.

즉, CG_M의 PL00(개별)·PL01~PL30(연결조정) 모든 레이어의 결과가 집약된 최종 잔액을 CG_P의 M Local FS(PL00)로 적재한다. 연결조정 분개 명세는 복사하지 않으며, 상위 연결은 M을 하나의 완결된 연결실체로 인식한다.
연결실체 가상화 구조
── CG_M 처리 (Y10 Version) ────────────────── M + S1 + S2 ↓ 연결결산 수행 (ICMR · 연결조정) M 연결재무제표 생성 (S1·S2 개별 데이터는 CG_M Y10에 완전 보존) ── Consolidated Entity Transformation ──────── M 연결재무제표 ↓ RAP API: 연결결과 → Local FS 재구성 CG_P의 M Local FS (PL00)로 적재 (PartnerSegment로 원천 법인 식별 보존) ── CG_P 처리 (000 Version) ────────────────── P + M(가상화된 연결실체) + T ↓ Reclass → ICMR → 연결조정 최종 연결재무제표
연결그룹 설계 원칙 — 반드시 2개
연결범위(Control Boundary)는 Ownership + Consolidation Group이 결정한다
Y10/000은 Version이고, CG_M/CG_P는 연결그룹이다. 두 축은 독립적으로 존재하며 혼동하지 않는다.

CG_M (중간 연결그룹): M, S1, S2
CG_P (최종 연결그룹): P, M, T — S1·S2는 CG_M에서 완결되어 M에 흡수됨
트랙 1 — GR 내 순차연결
중간지배 그룹도 GR(CG_M)에서 연결결산을 완료한 후, RAP API가 연결 결과를 CG_P의 M Local FS로 자동 변환·적재
적용 조건
중간지배 그룹 전 법인이 GR CU로 등록 가능하고, GR에서 중간지배 연결결산을 수행할 수 있는 경우. 비SAP 법인 포함 시 AGRA 비SAP 온보딩으로 ACDOCU 직접 적재 후 동일 구조 적용 가능.
1단계 — CU 마스터 설정
1
전체 법인 Full CU 등록
P, M, S1, S2, T 모두 Full CU (CU Type: 01). CG_M 연결 대상: M·S1·S2. CG_P 연결 대상: P·M·T. S1·S2는 CG_M Ownership에만 포함. 비SAP 법인은 AGRA 온보딩 후 동일하게 Full CU 등록.
2단계 — 연결그룹 설계 (2개 필수)
1
CG_M — 중간 연결그룹
구성: M, S1, S2. Ownership: M→S1(지분율), M→S2(지분율). 중간지배 연결결산이 완전히 수행되는 독립된 연결그룹. 연결범위(Control Boundary)를 명확히 정의.
2
CG_P — 최종 연결그룹
구성: P, M, T. Ownership: P→M(지분율), P→T(지분율). S1·S2 미포함 — M이 가상화된 단일 연결실체로 참여. RAP 변환 데이터가 M Local FS로 적재된 상태에서 연결 실행.
3단계 — Version 설계
1
Y10 Version — CG_M 전용
중간 연결그룹(CG_M) 연결결산 전용 Version. Data Monitor에서 M·S1·S2 마감 관리. 중간지배사 CFO 책임 범위. 완료 후 Lock.
2
000 Version — CG_P 전용
최종 연결그룹(CG_P) 연결결산 Version. Y10 Lock + RAP 변환 완료 후 개방. P·M·T 대상. M은 RAP가 적재한 연결 FS(PL00) 기준으로 참여.
4단계 — Reclassification Rule (CG_P 000)
1
T의 RBUPTR 재분류 — FI 레이어 무간섭
Source: RBUNIT=T, RBUPTR=S1 → Target: RBUNIT=T, RBUPTR=M, PartnerSegment=S1
Source: RBUNIT=T, RBUPTR=S2 → Target: RBUNIT=T, RBUPTR=M, PartnerSegment=S2
ACDOCU 레이어에서만 작동. Substitution Rule·Field Status 변경 불필요.
5단계 — ICMR 설정
1
CG_M Y10 — 표준 매칭 키
매칭 키: RBUPTR + RACCT. S1↔S2↔M 내부거래 표준 처리. PartnerSegment 불필요.
2
CG_P 000 — PartnerSegment 추가 매칭 키
매칭 키: RBUPTR + PartnerSegment + RACCT.
M(RBUPTR=T, PartnerSegment=S1) ↔ T(RBUPTR=M, PartnerSegment=S1) 건별 매칭·상계.

트랙 2 — 외부 FS 업로드
중간지배 그룹이 GR 외부에서 연결결산을 수행하고, 트랙 1의 RAP 변환 결과물과 동일한 구조로 CG_P에 업로드. GR 입장에서 두 트랙의 000 Version ACDOCU 구조는 완전히 동일.
적용 조건
중간지배 그룹이 GR 외부 시스템에서 연결결산을 수행하여 CU 등록이 불가능한 경우, 또는 법적·지배구조적 비공개 요건으로 GR 내 연결결산이 불가능한 경우.
1단계 — CU 마스터 설정
1
M — Full CU
CG_P 연결 대상. 연결 FS 업로드 주체. Data Monitor 마감 대상 포함.
2
S1·S2 — Partner Only CU (핵심)
Partner Only 옵션 지정. RBUPTR 값으로 인식 가능(ICMR 매칭 키 정상 작동). Data Monitor 마감 제외. 재무집계 제외. 실제 데이터 적재 불필요. GR 내 CG_M 연결그룹 불필요.
3
T — Full CU
FI 원장 데이터 표준 수집. 원천 데이터 일절 변경 없음.
2단계 — 연결그룹 설계 (CG_P 단일)
1
CG_P 단일 — GR 내 CG_M 불필요
중간 연결이 외부에서 수행되므로 GR 내 CG_M 불필요. CG_P: P, M, T. S1·S2는 Partner Only CU이므로 Ownership 미포함. 트랙 2에서는 연결그룹 1개.
3단계 — M 업로드 데이터 설계
1
트랙 1 RAP 결과물과 동일 구조 — 수동 작성
외부 파트너와의 거래: RBUNIT=M, RBUPTR=T, PartnerSegment=S1/S2 행 분리 제출
M 내부 상계 완료분: PartnerSegment 공란
PL00 기준 최종 연결 잔액만 제출. 연결조정 분개 명세 불필요.
4단계 이후 — 트랙 1 CG_P와 완전 동일
Reclassification Rule, ICMR Matching Rule, 연결조정, 실행 순서 모두 트랙 1의 CG_P 처리와 동일. GR 설정을 공유하거나 동일하게 구성.

RAP 개발 상세 — Consolidated Entity Transformation
트랙 1 전용. Y10 연결 결과를 CG_P M Local FS로 재구성하는 RAP/BTP 기반 변환 프로그램. 개발 규모: Medium.
개발 범위 (5개 모듈)
MODULE 01
Y10 데이터 조회
CG_M Y10 Version ACDOCU에서 최종 연결 잔액 읽기. 모든 PL 집약 결과. ABAP CDS View 또는 OData API 활용.
MODULE 02
연결실체 변환
S1·S2 개별 행을 M 연결 단위로 집약. 외부 파트너 거래 행 식별 및 분리. M 내부 상계 완료분 처리.
MODULE 03
PartnerSegment 생성
RBUNIT=S1, RBUPTR=T 행 → RBUNIT=M, RBUPTR=T, PartnerSegment=S1 변환. 원천 법인 식별 보존.
MODULE 04
ACDOCU 적재
GR 표준 데이터 수집 API 활용. 000 Version M Local FS(PL00) 적재. 비SAP 업로드 프로그램과 동일 인터페이스.
MODULE 05
재실행 제어
멱등성 보장. 재실행 시 기존 적재 데이터 전체 삭제 후 재적재. Y10 Lock 이벤트 트리거 또는 수동 실행.
변환 로직 상세
// INPUT: CG_M Y10 Version ACDOCU 최종 잔액 SELECT RBUNIT, RBUPTR, RACCT, SEGMENT, ... FROM ACDOCU WHERE RLDNR = 'Y10' AND GJAHR = :year AND POPER = :period // TRANSFORM: 연결실체 변환 로직 FOR EACH row IN source_data: IF row.RBUNIT IN (S1, S2) AND row.RBUPTR IN CG_P_scope: // 외부 파트너 거래 → PartnerSegment 생성 output.RBUNIT = 'M' output.RBUPTR = row.RBUPTR // T 유지 output.PARTNERSEGMENT = row.RBUNIT // S1 또는 S2 ELSE IF row.RBUNIT IN (S1, S2) AND row.RBUPTR NOT IN CG_P_scope: // M 내부 거래 → 집약 (PartnerSegment 공란) output.RBUNIT = 'M' output.RBUPTR = NULL output.PARTNERSEGMENT = NULL // OUTPUT: CG_P 000 Version M Local FS (PL00) INSERT INTO ACDOCU (RLDNR='000', RBUNIT='M', POPER=:period, ...)

SAP 로드맵 — 향후 표준 기능으로 대체 예정
Automatic Postings: Copy Transaction Data — Q4 2026 예정 (SAP S/4HANA Cloud Public Edition)
SAP은 Q4 2026 릴리즈에서 Automatic Posting Rules에 다른 Source Version·Source Consolidation Unit 지정, 동적 Period/Year 오프셋, 환율 접근 Formula, 전용 Document Type 지정 옵션을 추가할 예정이다. 이 기능이 GA되면 위 개발 범위의 상당 부분이 표준 Rule 설정으로 대체 가능하다.

핵심 확인 항목: PartnerSegment 자동 생성(SOURCE CU 코드 → PartnerSegment 필드 매핑)이 Formula 옵션 범위에 포함되는지 여부. 포함된다면 RAP 개발 없이 트랙 1 전체가 표준 GR 설정만으로 구현 가능해진다.

현재 권고: Q4 2026 GA 시점에 스펙을 재검토하여 RAP 개발 범위를 재산정할 것.

공통 설계 원칙
1. 연결조정 비승계: 연결조정 분개를 상위 연결으로 승계하지 않는다. 연결조정 결과가 반영된 연결재무제표만 상위 연결의 입력 데이터로 사용한다.
2. 연결그룹 = 연결범위: Version과 연결그룹을 혼동하지 않는다. 연결범위(Control Boundary)는 Ownership + Consolidation Group이 결정한다.
3. FI 레이어 무간섭: Substitution Rule·Field Status 변경 없이 ACDOCU 레이어에서만 처리한다.
4. GRDC 불필요: 표준 GR 기능 + RAP 개발(트랙 1)만으로 구현 가능하다.
5. PartnerSegment가 순차연결의 핵심 연결고리: ICMR 표준 매칭 키로 허용되므로 전체 설계가 표준 범위 내에서 성립한다.
SAP 로드맵 — 트랙 1 RAP 개발 대체 가능성
Automatic Postings: Copy Transaction Data — Q4 2026 예정 (SAP S/4HANA Cloud Public Edition)
SAP 로드맵에 따르면 Q4 2026 릴리즈에서 Automatic Posting Rules에 Source Version·Source CU 지정, 동적 오프셋, 환율 Formula, Document Type 지정 옵션이 추가될 예정이다. 이 기능이 GA되면 현재 트랙 1의 RAP 개발(Medium) 상당 부분이 표준 기능으로 대체 가능해진다.
