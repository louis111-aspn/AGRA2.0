01

GR 투자자본상계의 현행 구조

SAP Group Reporting의 투자자본상계(Consolidation of Investments)는 현재 세 가지 방식으로 제공된다. Activity Based, Rule Based, 그리고 2026년 중 CoI 룰셋 출시가 예정된 Automatic Posting 방식이다.

방식 대상 현황 영업권 관리
Activity Based 기존 고객 전용 신규 차단 제공 (영업권·염가매수차익 산출)
Rule Based 신규 Public Cloud 고객 현행 표준 제한적
Automatic Posting 2026년 CoI 룰셋 예정 예정 Framework 先공개, 룰셋 추후
핵심 전제조건

세 가지 방식 모두 Activity Code + Sub Item 슬라이스 업로드를 전제로 한다. FI 원장 Document Release만으로는 이를 자동으로 채워주지 않으며, 별도 Substitution Rule 설정 또는 GRDC 구독이 필요하다.

SAP 로드맵 — Q3 2026 출시 예정

Portfolio and Group Structure Management 기능이 Q3 2026 출시 예정이다. 발행주식수·보유주식수 수집, 연결 비율 자동 계산, 연결방법 자동 제안 등을 포함한다. 현재 기능 설명 기준으로는 현재 시점의 지분 구조 파악에 집중하는 스냅샷 기반 접근으로 보이며, 취득일 고정·취득원가 이력·이벤트별 자본 변동 추적 등 시계열 이력 관리 개념은 포함되지 않는 것으로 판단된다. GA 이후 실제 구현 범위를 확인하고 애드인 설계 방향을 재검토할 필요가 있다.

02

구조적 한계의 본질

GR은 근본적으로 재무제표 기반 수치 처리 엔진이다. 피투자회사의 FS Item 데이터를 받아 Activity Code/Sub Item으로 분류하고, 그 수치를 기반으로 상계 분개를 발생시키는 구조다. 이 설계 철학 자체가 한계의 출발점이다.

이벤트 이력 부재

  • 투자 취득일 기준 스냅샷 미관리
  • 자본 변동 전/후 이력 미저장
  • 지분율 변동 이력 미추적
  • 감사 소급 추적 불가

투자차액 산출 한계

  • 취득원가 vs 지분해당 순자산 자동 계산 불가
  • 영업권 / 염가매수차익 자동 산출 없음
  • 영업권 상각 스케줄 미제공
  • 투자차액 산출은 외부 위임 구조

세밀한 조정 분개 한계

  • 단계적 취득/처분 분리 불가
  • 지배력 변동 시점 분개 생성 불가
  • 지분법 중단·회복 미지원
  • GR 자동화 흐름 조건 통제 불가
설계 의도

이것은 GR의 버그가 아니라 의도된 범위 한정이다. SAP은 이 공백을 GRDC와 파트너 생태계로 채우도록 설계했다. 그러나 GRDC 역시 데이터 슬라이싱 자동화에 집중할 뿐, 이벤트 원장을 제공하지는 않는다.

03

글로벌 프랙티스와의 괴리

IFRS 10 및 IAS 27 기준의 국제 표준 프로세스는 이벤트 발생 시점 고정(Acquisition Date Accounting)이 출발점이다. 취득일의 피투자회사 식별가능 순자산 공정가치를 확정하고 취득원가와의 차이로 영업권 또는 염가매수차익을 산출한다. 이 수치는 취득일에 고정되어 이후 결산에서 변하지 않는다.

GR의 슬라이싱 방식 — 예컨대 "당기 순증감 100 = 유상증자 50 + 무상증자 50" — 은 결과물의 분류이지 이벤트 처리의 출발점이 아니다. 이 분리의 근거가 시스템에 기록되지 않는다는 점이 본질적 문제다.

국내 감사 환경

DART 공시 의무로 인해 감사인의 연결 조정 명세 검토가 상세하다. 감사인이 실제로 확인하는 것은 "이 유상증자는 언제 발생했고, 지배주주 참여 금액은 얼마이며, 그 결과 지분율이 어떻게 변동했는가"다. GR의 슬라이싱 방식은 이 질문에 대한 시스템 내 답변을 제공하지 못한다.

04

BPC 선례와 GR 재구현 필요성

BPC 시절 국내에서는 동일한 문제를 해결하기 위한 투자자본상계 로직을 구현했고, 이는 검증된 선례로 존재한다. GR은 BPC를 대체하는 포지셔닝으로 출시되었지만, 이 특정 기능은 GR 기본 기능으로 제공되지 않는다. BPC는 자유로운 데이터 모델 설계가 가능했지만, GR은 Clean Core 원칙과 정해진 ACDOCU 구조 안에서만 움직이기 때문에 동일한 로직을 GR 환경에 맞게 새롭게 구현해야 한다.

검증된 로직 내용 GR 구현 방식
① 투자법인 투자 History 투자법인/피투자법인, 이벤트 유형, 발생일, 취득원가, 지분율 RAP Custom Table로 구현
② 피투자법인 자본 History 기준시점별 자본 항목 금액, 순자산 합계, PPA 조정, 재무제표 원장 대조 검증 ACDOCU 조회 + 검증 로직으로 구현
③ 투자차액 계산 내역 취득원가 — 순자산×지분율 = 영업권, 상각 스케줄, NCI ABAP 계산 클래스로 구현
④ 소스데이터 계산/전송 투자자본상계 룰 입력값 생성, Activity Code별 금액 분류, 검증 리포트 GR Manual Journal Entry 생성으로 구현

종속기업 · 지분법 범위

지분법 적용 대상도 GR CU로 등록되며 ACDOCU에 데이터가 적재된다. GR이 연결 Task에서 제거 분개와 지분법 손익 분개(잉여금, 해사차의 지분 반영)를 자동 생성하는 구조다. 따라서 애드인의 역할은 종속기업과 구조적으로 동일하다.

GR이 지원하지 않는 지분법 고유 영역은 명확하다. 투자차액 산출(내재 영업권 관리), 그리고 지분법 중단과 회복이다. 특히 지분법 중단·회복은 미인식 누적 손실 잔액을 별도로 관리해야 하며, GR 자동화 흐름을 조건에 따라 통제하는 상위 레이어가 필요하다.

구분 GR 자동화 애드인 필요
종속기업 — 완전 연결 자산·부채 합산, 내부거래 제거 투자차액 산출, 분개 생성
지분법 — 정상 지분법 손익 자동 분개 내재 영업권, 손상 검토
지분법 — 중단 미지원 — 수동 통제 필요 중단 시점 확정, 미인식 손실 누적
지분법 — 회복 미지원 — 수동 통제 필요 누적 손실 상계 후 재개 계산

MVP 경계 원칙

MVP는 지분율 고정, 연결방법 변경 없음, 중단·회복 없음 조건으로 한정한다. 이 조건만으로도 BPC 시절 Excel로 관리하던 80%를 대체하고, 감사인이 요구하는 투자차액 소명 자료를 시스템에서 직접 생성할 수 있다.

09

개발 필요성 및 시장성 견해

필요성 — 구조적으로 불가피하다

이 문제는 GR 버전이 올라가도, Automatic Posting CoI 룰셋이 나와도 해소되지 않는다. SAP의 설계 철학 자체가 이벤트 이력 관리를 범위 밖으로 정의하고 있기 때문이다. 국내 감사 환경은 이 문제를 더욱 구조적으로 만든다. 투자자본상계 분개의 이벤트 소급 추적이 불가능하면, 결산 담당자는 매 결산기 Excel로 소명 자료를 만들어야 하며 그 Excel이 GR 데이터와 일치한다는 보장이 없다. 이것은 내부통제의 공백이다.

시장성 — 좁지만 깊고 경쟁이 없다

대중적인 시장은 아니다. S/4HANA Public Cloud + GR 채택 + 해외 종속기업 보유 + 상장사. 이 조건을 모두 충족하는 국내 기업의 수는 지금 시점에서 많지 않다. 그러나 연결 결산은 기업의 공시 의무와 직결된다. 이 기능이 없어서 생기는 리스크의 비용은 애드인 구독료와 비교할 수 없어 가격 협상에서 구매자 저항이 낮은 영역이다.

경쟁이 없다는 점이 중요하다. Tagetik·OneStream은 GR을 대체하는 솔루션이지 보완하는 솔루션이 아니다. GR을 이미 채택한 고객에게 이들은 선택지가 되기 어렵다. GRDC는 데이터 피딩 레이어에 머물러 있다. 이 공백을 채우는 제품이 국내에 없다. 그리고 S/4HANA Public Cloud 도입이 늘어날수록 이 문제를 가진 기업의 수는 증가한다.

리스크 — 타이밍과 레퍼런스

가장 현실적인 리스크는 하나다. 지금 당장 이 기능이 필요한 고객이 충분한가. 시장이 성장한다는 것과 지금 당장 팔린다는 것은 다르다. 수요 검증 방식과 개발 경로는 아래 대안 비교를 참조한다.

종합 견해

개발 필요성은 높고, 시장성은 좁지만 깊으며,
경쟁이 없는 영역이다.

필요성
GR + GRDC 조합으로도 해소되지 않는 구조적 공백. Automatic Posting 출시 후에도 유지됨.
시장성
고객당 가치 높음. 경쟁 부재. 시장 성장과 함께 수요 확대. 선점 효과 기대 가능.
권고
개발 경로 선택이 핵심. Excel 툴(법인 수 소규모 한정), BTP CAP 프로토타입, 풀 제품 직행 중 검토 필요.
